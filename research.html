How Your Alerts Are Built
Every 5 minutes, Bloodhound runs this pipeline for up to 50 symbols. Each step narrows what reaches your phone.
Step 1
Discovery & Data Collection
First, pick which symbols to scan. 9 are permanent (SPY, QQQ, NVDA, TSLA, AMD, AAPL, META, MSFT, IBIT). The remaining ~41 slots go to the highest-priority discoveries: pre-market gappers, volume spikes, 52-week extremes, sector leaders/laggards. Then, for each symbol, pull data sequentially (100ms delays to avoid API overload):
TechnicalsRSI, MAs, trend, Bollinger, volume ratio
Gamma LevelsPut/call walls, max pain, VWAP, gamma flip
Options AnalysisUnusual activity, premium flow, vol/OI
Market ContextVIX regime, SPY/QQQ levels, AI outlook
Sector RS28-asset relative strength from divergence scanner
InternalsTICK, TRIN, A/D, vol ratio (separate process)
Step 2
Confluence Scoring Engine
Three scoring categories add up independently, then get clamped to 0-100. This is where confluence lives — a high score means multiple unrelated data sources are pointing the same direction.

Step 4
Tier Assignment
Score + zone + conditions determine the confidence tier. This is the final filter before alerting.
HIGH_CONVICTION
Prime setup (wall+RSI) + score ≥40 — OR — score ≥50 at wall. Must have action (BUY/SELL).
TRADEABLE
Score ≥35 at wall + action. Good setup but not top tier.
WATCH
Score ≥20 near wall, or score ≥35 in mid-range/pinned. Monitor only.
FILTERED
Doesn't meet any criteria. Not shown.
Safety Caps (override tier down to WATCH):
Bearish direction (0% historical win rate) • Neutral direction • Pinned direction • RETURNED setups (11% win rate)
Step 5
Alert Decision
Only HIGH_CONVICTION signals reach your phone. Everything else stays in the database for the dashboard.
HIGH_CONVICTION
Alert → Telegram → Phone
TRADEABLE + WATCH
Database → Dashboard only
Deduplication (prevents alert spam):
Same setup cooldown: 4 hours • Score must jump +15 pts to re-alert • Max 2 alerts per symbol per day • New zone or direction change = fresh alert

Critical Findings

7 issues
C1 CRITICAL 7-Day Signal Checkpoints Never Execute
0 out of 187 eligible signals have completed the 7-day checkpoint. The checkpoints table has 252 entries for 4h and 198 for 24h, but zero for 7d. The swing-trade validation tier documented in CLAUDE.md is completely non-functional. This means the system cannot validate signal accuracy beyond 24 hours.
Source: data audit — signals table, checkpoints table
C2 CRITICAL tick_high and tick_low Always Zero in Market Internals
533 of 558 market_internals rows have tick_high = 0 and tick_low = 0. These fields should capture the intraday TICK range but are never populated correctly. Any dashboard chart relying on TICK high/low is showing flat lines.
Source: data audit — market_internals table
C3 CRITICAL No Global Error Handlers in Any PM2 Process
None of the 7 scanner processes register process.on('uncaughtException') or process.on('unhandledRejection'). An unhandled promise rejection silently crashes the process. PM2 restarts it, but the crash context and stack trace are lost. Only eod-gap-tracker.js has SIGINT/SIGTERM handlers.
Source: code audit — all scanner files
C4 CRITICAL signal-db.js is a 3,519-Line God File
All schema definitions, all migrations, all CRUD operations for 12+ tables live in a single file exporting 60+ functions. This is the single biggest architectural risk — any bug here affects all 7 services simultaneously. Navigation is difficult and changes have high blast radius.
Source: code audit — monitor/signal-db.js (3,519 lines, 60+ exports)
C5 CRITICAL No Body Size Limit on POST Endpoints
All POST handlers in web-server.js accumulate req.on('data') chunks without any size limit. A large payload (accidental or malicious) can cause an out-of-memory crash. There is also no req.on('error') handler on any request stream.
Source: code audit — web-server.js:44, 814, 839, 997, 1022
C6 CRITICAL https Module Referenced But Never Imported
opportunity-scanner.js:317 references https in a conditional but only imports http. If any URL starts with https://, this throws ReferenceError: https is not defined and crashes the scanner. Currently all API URLs are HTTP so this hasn't manifested, but it's a latent crash waiting to happen.
Source: code audit — opportunity-scanner.js:14 (import), :317 (usage)
C7 CRITICAL Divergence Scanner Logging 42 MB to stderr
The divergence-scanner Python service writes httpx INFO-level messages to stderr, inflating the PM2 error log to 42 MB (89% of all PM2 log disk usage). This is not being flushed by the weekly log rotation script because divergence-scanner is not included in the archive/flush scripts.
Source: ops audit — ~/.pm2/logs/divergence-scanner-error.log (42 MB)
