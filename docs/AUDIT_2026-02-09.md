# Wingman Project Audit - 2026-02-09

**Scope:** 4 agents audited ~15,000+ lines across 20 JS files, 12 HTML files, config, scripts, and docs.

**Overall Verdict:** System is architecturally sound. Bloodhound core is well-built. Main issues are accumulated debt from the JSON-to-SQLite migration period, plus one DST bug and an exposed token.

---

## CRITICAL

### 1. Telegram Bot Token Exposed in Git
- **File:** `monitor/config.json`
- **Issue:** Bot token `8527216242:AAE...` is in plaintext, committed to repo history
- **Impact:** Anyone with repo access can control the Telegram bot
- **Fix:** Move to `.env` file or environment variable. Rotate the token via BotFather.
- **Breaks:** All 4 scanners that send Telegram alerts read from config.json. After moving to env var, each scanner's config loading needs updating.
- **Status:** [x] DONE - Token rotated via BotFather. New token stored in .env (gitignored). config.json placeholder set to "SET_IN_ENV_FILE". config-loader.js loads .env automatically. Test alert confirmed working.

## HIGH

### 2. Watchlist Split Brain (JSON vs SQLite)
- **Files:** `monitor/opportunity-scanner.js` (line 113), `monitor/premarket-scanner.js` (line 342-344), `monitor/earnings-calendar-scraper.js` (line 20), `monitor/watchlist.js` (entire file)
- **Issue:** Bloodhound reads watchlist from SQLite (`signal-db.js:getWatchlistPartitioned`). But Opportunity scanner, Premarket scanner, earnings-calendar-scraper, and CLI `watchlist.js` all read from `data/watchlist.json`. The two sources drift apart.
- **Impact:** Symbols added by automation to SQLite (e.g., premarket gaps) are invisible to Opportunity scanner. Symbols added via CLI are invisible to Bloodhound.
- **Fix:** Migrate all watchlist consumers to use `signal-db.js` functions instead of reading JSON.
- **Breaks:** Need to verify each scanner's watchlist reading code path. The JSON file can remain as a backup/legacy but should no longer be the source of truth for any scanner.
- **Dependencies:** Fix #3 (Bloodhound HTTP API) is part of this same issue.
- **Status:** [x] DONE - All 4 files migrated to signalDb.getWatchlist(). Premarket latent bug fixed (was returning objects, now returns strings). watchlist.js CLI fully rewritten for SQLite.

### 3. Bloodhound /watchlist HTTP API Writes JSON, Discovery Reads SQLite
- **File:** `monitor/bloodhound-scanner.js` - /watchlist, /watchlist/add, /watchlist/remove endpoints
- **Issue:** These HTTP endpoints (on port 8081) read/write `data/watchlist.json`, but Bloodhound's actual `loadWatchlist()` discovery function reads from SQLite. Adding a symbol via the API has zero effect on scanning.
- **Impact:** Zone Scanner dashboard's "Add to Watchlist" button doesn't actually work for Bloodhound scanning.
- **Fix:** Update these endpoints to use `signal-db.js` watchlist functions (addToWatchlist, removeFromWatchlist, getWatchlist).
- **Breaks:** Zone Scanner dashboard expects the current response format. Verify the API response shape matches.
- **Status:** [x] DONE - Replaced JSON read/write with signalDb.getWatchlistFull(), addToWatchlist(), removeFromWatchlist(). Removed dead WATCHLIST_PATH constant. Dashboard response shape compatible (symbols array with symbol+enabled fields). Added setWatchlistNotes() to signal-db.js for CLI note command.

### 4. Opportunity Scanner DST Bug
- **File:** `monitor/opportunity-scanner.js` - `isMarketHours()` function
- **Issue:** Uses hardcoded `UTC - 5` offset for EST. During EDT (March-November), this is wrong by 1 hour. Scans will start/stop at wrong times.
- **Impact:** During EDT, the scanner will think market opens at 10:30 AM ET and closes at 5:30 PM ET instead of 9:30 AM / 4:30 PM.
- **Urgency:** EDT starts March 8, 2026 - less than 1 month away.
- **Fix:** Use `toLocaleString('en-US', {timeZone: 'America/New_York'})` approach (same as Bloodhound) or the `isDST()` function (same as Premarket scanner).
- **Breaks:** Nothing. Pure bugfix. Behavior gets more correct.
- **Reference:** Bloodhound handles this at bloodhound-scanner.js (toLocaleString). Premarket handles it at premarket-scanner.js (isDST function).
- **Status:** [x] DONE - Replaced hardcoded UTC-5 with toLocaleString approach matching Bloodhound

### 8. SQL Template Literal Interpolation
- **Files:**
  - `monitor/opportunity-db.js` - `getRecentScans(days)`, `getTierStats(days)`, `getTopSymbols(days, limit)` (lines ~227, 236, 248)
  - `monitor/signal-db.js` - `getGapFillRates()` (line ~1825), `getTickerGapHistory()` (line ~1920), `getRepeatOffenders()` (line ~2016)
- **Issue:** Use `${days}` and `${limit}` directly in SQL strings instead of parameterized `?` placeholders.
- **Impact:** LOW practical risk (params are numeric function arguments, not user input, and better-sqlite3 would reject non-numeric). But bad practice.
- **Fix:** Replace template literals with `?` placeholders in each function.
- **Breaks:** Nothing if done correctly. Test each query after changing.
- **Status:** [x] DONE - Parameterized all 5 functions (3 in opportunity-db.js, 2 in signal-db.js). getRepeatOffenders was already correct. All queries tested and returning data.
